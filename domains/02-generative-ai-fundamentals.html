2.1 Explain the basic concepts of generative AI

Generative AI creates new content (text, images, audio, code, video). It learns the patterns in a very large set of training data, then makes new content that follows those patterns. Full definitions are in the glossary. This section shows how the pieces fit together.

Tokens and tokenization

A model never sees raw text. A tokenizer (a tool that cuts text into pieces) first splits text into tokens. A token can be a whole word, part of a word, punctuation, or bytes. Each token gets an integer ID, and the model works with those IDs. Common words are often one token. Rare words, names, and code are split into several. In English, one token is roughly three-quarters of a word. Each model family has its own tokenizer, so counts differ between models.

Tokens matter for three practical reasons. First, cost: on-demand pricing is per input token and per output token. Second, limits: the context window and the maximum output length are counted in tokens. Third, latency (wait time): the model writes one token at a time, so longer answers take longer.

Worked example: a 2,000-token document plus a 100-token instruction is 2,100 input tokens. If the model writes a 300-token summary, you pay for 2,100 input tokens and 300 output tokens. Output tokens usually cost more than input tokens.

Embeddings and vector similarity

An embedding is a list of numbers (a vector, often hundreds to thousands of dimensions) made by an embedding model. Text with similar meaning gets numbers that sit close together in vector space. Think of a map where "refund policy" and "return an item" are in the same neighborhood even though they share no words. "Weather forecast" is far away.

"Close" is measured with a distance or similarity function such as cosine similarity or Euclidean distance. To search, you turn the query into an embedding. Then you ask a vector database (a store built to find similar vectors) for the nearest stored vectors. This is semantic search (search by meaning). It is also the retrieval step in Retrieval Augmented Generation (RAG). Images can have embeddings too, so text can be matched to pictures in a multimodal embedding space.

Chunking

Documents are too long and cover too many topics to turn into one vector. Chunking splits them into smaller passages before embedding. A passage might be a few hundred tokens, often with some overlap. Chunks that are too large mix several topics into one vector and waste space in the context window. Chunks that are too small lose the meaning around them. Overlap keeps a sentence that sits on a boundary easy to find. In Amazon Bedrock Knowledge Bases, chunking is part of the managed ingestion process (it loads your documents for you), and you can choose a chunking strategy.

Transformers and attention, intuitively

Older models read text one word at a time and had trouble linking words that were far apart. The transformer design uses self-attention. For every token, the model works out how much it should "look at" every other token to understand it. In "The trophy did not fit in the suitcase because it was too big", attention helps the model see that "it" means the trophy. All tokens can be processed at the same time (in parallel). That lets transformers train well on large clusters of hardware, which made today's large models possible.

An LLM (large language model) is a model trained on huge amounts of text to guess the next word (token). It repeats that guess over and over to write a full answer. With extra training to follow instructions, the same skill lets it summarize, translate, and answer questions.

Diffusion models

A diffusion model is trained by taking real images and adding noise step by step until only static is left. It then learns to undo each step. To make a new image, it starts from pure noise and removes noise again and again, guided by a text prompt, until an image appears. Analogy: a sculptor who starts with a rough block and slowly reveals the shape. Diffusion is the main method behind modern image generation, and similar ideas are used for video. Amazon Titan Image Generator and Stability AI image models on Bedrock are image-generation examples.

Multimodal models

A multimodal model can take in or produce more than one type of data, such as text plus images. Examples: describing a chart from a screenshot, answering questions about a photo, or turning a text description into an image. Check the model card in Bedrock to see which input and output types each model supports. A text-only LLM cannot read an image.

Prompts and the context window

The prompt is everything you send: instructions, examples, retrieved documents, and the user's question. The context window is the most tokens (input plus output) the model can handle at once. The model does not see anything past that limit. The model remembers nothing between calls except what you put in the prompt. A chatbot "remembers" by sending the earlier messages again. Prompt engineering means writing the prompt carefully to get better output without changing the model.

Inference parameters: temperature, top-p, top-k

At each step, the model gives every possible next token a probability, then picks one at random based on those odds (this is called sampling). These settings control that pick:

ParameterWhat it doesTypical use
TemperatureChanges how spread out the probabilities are. Low values favor the most likely tokens. High values give unlikely tokens a better chance.Low for factual extraction or code; higher for brainstorming and creative writing
Top-pPicks only from the smallest group of tokens whose probabilities add up to p (for example 0.9).Lower p for focused output
Top-kPicks only from the k most likely tokens.Lower k for more predictable output

These settings change randomness, not knowledge. A low temperature makes output more repeatable, but it does not fix a wrong fact.

Foundation model lifecycle

Data selection -> Model selection -> Pre-training -> Fine-tuning -> Evaluation -> Deployment -> Feedback
  1. Data selection: choose and clean the data. Think about quality, variety, licensing, and privacy.
  2. Model selection: pick a model design or an existing FM (foundation model) that fits the data type, size, cost, and speed you need.
  3. Pre-training: the model teaches itself from a huge amount of unlabeled data (self-supervised learning). This is very expensive, so most organizations skip it and start from an existing FM.
  4. Fine-tuning: more training on a smaller, labeled dataset for one task or field, so the model gets better at it.
  5. Evaluation: check quality against your goals using benchmarks, automatic metrics, and human review.
  6. Deployment: run the model for users, for example through Bedrock or a SageMaker endpoint, with monitoring and guardrails.
  7. Feedback: collect signals from users and monitoring to improve prompts, data, and future model versions. This loops back to earlier stages.

Generative AI use cases

Use caseWhat it looks like
SummarizationShorten call transcripts, long reports, or legal documents
Chatbots and customer-service agentsChat answers based on company knowledge, often with RAG
Code generationSuggest, explain, test, and rewrite code (for example with Amazon Q Developer)
SearchSearch by meaning over documents using embeddings; plain-language answers instead of lists of links

Exam tip: Match the keyword to the concept: "denoising" means diffusion, "numeric representation of meaning" means embedding, "attention" means transformer, "more than one data type" means multimodal, "pay per input/output token" means on-demand.

Common trap: Pre-training and fine-tuning are not the same. Pre-training builds general skill from unlabeled data. Fine-tuning makes the model better at one job using a smaller labeled dataset. Also, a larger context window does not mean the model remembers earlier conversations.

Key takeaways

  • Text becomes tokens. Tokens affect cost, limits, and latency.
  • Embeddings place meaning in vector space. Chunking gets documents ready for embedding.
  • Transformers use attention. LLMs predict the next token. Diffusion models remove noise.
  • Temperature, top-p, and top-k control randomness only.
  • The lifecycle runs from data selection to feedback, and then loops back.

2.2 Capabilities and limitations for business problems

Advantages

  • Adaptability: one foundation model can summarize, classify, translate, and answer questions. You steer it with prompts, retrieval, or fine-tuning, so you don't need a separate custom model for each task.
  • Responsiveness: answers arrive in seconds, so support, drafting, and analysis work gets faster and can run around the clock.
  • Simplicity: you use plain language, so you need fewer special skills. A prototype can be a prompt and an API call instead of a months-long training project.

Limitations and risks

  • Hallucination: the model aims for likely next tokens, not true ones. It can state made-up facts, citations, or API names in a confident tone. To reduce this, use RAG, grounding checks, lower temperature, and human review.
  • Interpretability: with billions of parameters (the numbers the model learned), it is hard to explain why it gave a certain output. This is a problem for regulated decisions.
  • Inaccuracy: outputs can be wrong, out of date (training data has a cutoff), or biased.
  • Nondeterminism: because of sampling, the same prompt can give different answers. That is fine for brainstorming but awkward for testing and audits.
  • Cost: large models cost money per token and per hour of hosted capacity. Long prompts and long answers raise the bill.
  • Data privacy and security: sending sensitive data to a model, or leaking it in outputs, creates risk. Prompt injection (tricking the model with hidden instructions) is a related risk.
  • Intellectual property: training data and generated output can raise copyright and licensing questions.

Choosing a model for a business problem

Start with the problem, not the model. Think about the data type needed (text, image, both), the quality you need, speed, cost per request, context window size, ways to customize (prompting, RAG, fine-tuning), language support, and compliance or data-residency rules. Bigger is not always better. A smaller, cheaper model often handles a narrow task well. Use a large one only when the better quality is worth the price. Test candidates on your own prompts, for example with Bedrock model evaluation, before you commit.

Measuring business value

MetricWhat it asksExample
EfficiencyIs work faster or cheaper?Support handle time drops from 10 to 6 minutes
Conversion rateDo more visitors buy or sign up?Generated product copy lifts checkout rate
Average revenue per user (ARPU)Does each user bring in more revenue?Personalized recommendations raise basket size
Customer lifetime valueDo customers stay and spend longer?Better service improves retention
Cross-domain performanceDoes the model do well across many kinds of tasks and fields?One model serves legal, HR, and support teams
AccuracyAre outputs correct for the task?Share of summaries judged faithful

Pair a business metric with a technical one. A model with great benchmark scores that does not improve conversion or efficiency has not added value.

Exam tip: Scenario questions usually link a stated goal to a metric: "sell more per visit" is ARPU or conversion, "long-term retention" is customer lifetime value, "save staff time" is efficiency.

Common trap: Low temperature reduces variation but does not remove hallucination. Only grounding (RAG), checking, and human oversight deal with wrong facts.

Key takeaways

  • Strengths: adaptability, responsiveness, simplicity.
  • Weaknesses: hallucination, interpretability, inaccuracy, nondeterminism, cost, privacy, IP.
  • Pick models by how well they fit the task, the limits you have, and the business results you measure.

2.3 AWS infrastructure and technologies for GenAI apps

AWS offers GenAI at several levels. A simple way to picture it: ready-made apps (Amazon Q) at the top, managed model access and building blocks (Bedrock) in the middle, and self-managed model hosting (SageMaker) at the bottom. The higher you go, the less you build and the less control you have.

ServiceRoleChoose it when
Amazon BedrockServerless API access (no servers to manage) to foundation models from several providers, plus Knowledge Bases, Agents, Guardrails, and model evaluationYou are building your own GenAI application and want managed models
SageMaker JumpStartA library of pre-trained models and solution templates, deployed to endpoints you controlYou need more control over hosting, instance types, or models not offered in Bedrock
PartyRockA no-code playground for building small GenAI apps, backed by BedrockYou want to experiment or learn without writing code
Amazon QReady-made GenAI assistants (Business, Developer)You want an assistant, not a platform to build one
Amazon TitanAWS's own FM family, available in BedrockYou want an AWS-built text, embeddings, or image model

Amazon Bedrock in depth

  • Model catalog: one API for models from many providers (for example Amazon, Anthropic, Meta, Mistral AI, Cohere, AI21 Labs, Stability AI). You can swap models by changing the model ID, so side-by-side comparison is easy. Your prompts and data are not used to train the base models offered through Bedrock.
  • Knowledge Bases: managed RAG. You point it at a data source (such as S3). It splits the content into chunks, embeds them, and stores them in a vector store. At query time it finds the relevant passages and gives them to the model. This bases answers on your current data without retraining.
  • Agents: let a model plan and carry out tasks with several steps, such as looking up an order and then issuing a refund. They do this by calling your APIs (through action groups) and can also check a knowledge base.
  • Guardrails: settings that check inputs and outputs for problems. They include content filters, denied topics, word filters, sensitive-information (PII) filters, and a contextual grounding check against hallucination. They work across models.
  • Model evaluation: compare models or settings on your own datasets, using automatic metrics or human reviewers.
  • Customization: fine-tuning and continued pre-training for supported models. The result is a custom model.

Other services

  • SageMaker JumpStart: start from a pre-trained or open model, deploy it to a SageMaker endpoint, and optionally fine-tune it. You manage the endpoint capacity. That gives you control but means more operational work than Bedrock.
  • PartyRock: build shareable apps by describing them in a browser. It is for experimenting and learning, not production workloads.
  • Amazon Q Business: an assistant for employees. It connects to company data sources and answers questions from them, while following existing user access permissions.
  • Amazon Q Developer: an assistant for software work. It suggests and generates code, explains and debugs code, and helps with AWS questions. It is available in IDEs and the console.
  • Amazon Titan: includes text generation models, text and multimodal embedding models, and an image generator, all used through Bedrock.

Why build on AWS

  • Accessibility and lower barrier to entry: API access and no-code tools let teams without ML specialists get started.
  • Speed to market: no GPU buying or model hosting. You can go from prototype to production quickly.
  • Security: encryption, IAM access control, private connectivity options, and logging with the usual AWS tools.
  • Compliance: AWS keeps many compliance programs in place. You still own your own setup and use of them under the shared responsibility model.
  • Responsible AI and safety: built-in controls such as Guardrails.
  • Cost-effectiveness: pay-as-you-go, with options to commit for steady workloads.

Cost model

OptionHow you payBest for
On-demandPer input and output token (images are priced per image); no commitmentVariable or unpredictable traffic, prototypes
BatchSend many prompts as one job and get results later, usually at a lower price than on-demandLarge offline jobs where speed does not matter
Provisioned throughputReserve model units for an hourly rate, with optional commitment termsSteady, high-volume workloads that need consistent performance; the standard way to run custom models

Worked example: a nightly job that sorts 500,000 support tickets can wait until morning, so batch inference is a good fit. A customer chatbot with a steady, heavy load and strict speed needs may be worth provisioned throughput. A prototype used by ten people should be on-demand.

Other cost and design factors: Region (model availability and price vary, and data residency rules may limit where you can run), redundancy and availability (spread the design across Availability Zones or Regions if needed), response time, and model size. Cost also grows with prompt length, so shorter prompts and retrieving only the relevant chunks save money.

Exam tip: "No infrastructure to manage, many models, one API" is Bedrock. "Ground answers in my documents" is Knowledge Bases. "Block harmful or off-topic content" is Guardrails. "Multistep tasks calling APIs" is Agents. "Employees ask questions about internal data" is Q Business. "Help developers write code" is Q Developer.

Common trap: Do not choose provisioned throughput just because traffic sounds high. It is the answer for steady, predictable load or custom models. Also, PartyRock is not a production platform, and JumpStart is not serverless like Bedrock.

Key takeaways

  • Bedrock is the managed hub for many models. JumpStart gives more control. Q gives ready-made assistants. PartyRock is for no-code experiments.
  • Knowledge Bases ground, Agents act, Guardrails protect, evaluation compares.
  • Pricing: on-demand per token, batch for offline jobs, provisioned throughput for steady load and custom models.
  • AWS value: speed, security, compliance, responsible AI tools, and flexible cost.

  1. What is a token, and why does it matter for cost?

    A piece of text the model reads or writes. Bedrock bills per input and output token.

  2. What is an embedding used for?

    Turning meaning into vectors so you can search by similarity (e.g., RAG).

  3. Which type of model generates images by removing noise?

    Diffusion models.

  4. List the FM lifecycle stages.

    Data selection, model selection, pre-training, fine-tuning, evaluation, deployment, feedback.

  5. Name three disadvantages of generative AI.

    Hallucinations, interpretability issues, inaccuracy, nondeterminism.

  6. What does "nondeterminism" mean here?

    The same prompt can produce different outputs.

  7. Which service gives API access to many FMs without managing servers?

    Amazon Bedrock.

  8. How do Bedrock and SageMaker JumpStart differ?

    Bedrock is serverless API access to FMs. JumpStart deploys pre-trained models onto endpoints you manage.

  9. When would you choose provisioned throughput over on-demand?

    Steady, high-volume workloads that need guaranteed throughput, or when using a custom model.

  10. Which AWS tool is a no-code place to experiment with GenAI apps?

    PartyRock. It is a playground backed by Bedrock, meant for experiments, not production.

  11. A team wants factual extraction that returns nearly the same answer on every run. Which inference setting should they adjust?

    Lower the temperature (and optionally top-p/top-k). The model then favors the most likely tokens, so there is less randomness.

  12. A company wants its chatbot to answer from the latest internal policy documents without retraining a model. What should it use?

    Bedrock Knowledge Bases (RAG). It finds the relevant chunks at query time and gives them to the model.

  13. An online retailer measures whether generated recommendations make each shopper spend more. Which metric fits?

    Average revenue per user (ARPU). It tracks the revenue earned per customer.

  14. A bank needs to stop its assistant from discussing investment advice and from echoing account numbers. Which feature helps?

    Bedrock Guardrails. Denied topics and sensitive-information filters work on inputs and outputs.

  15. A firm must classify 500,000 documents overnight, with no need for instant results. Which Bedrock mode is the most cost-aware choice?

    Batch inference. It handles large offline jobs, usually at a lower price than on-demand.
