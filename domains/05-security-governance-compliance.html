Domain 5: Security, Compliance, and Governance for AI Solutions (14%)

Source: AWS Certified AI Practitioner exam guide, version 1.4 (AIF-C01). Study aid, so verify against AWS docs.

This domain is less about memorizing configuration steps and more about knowing which tool answers which question. The exam describes a risk or an audit need and asks you to pick the service. Read each section for the reasoning, then use the tables as a lookup.

5.1 Secure AI systems

Shared responsibility applied to AI

AWS secures the cloud: the data centers, the hardware, and the systems under managed services. You secure what you put in the cloud: your data, who can access it, how you set up services, and how your application behaves. Think of renting an apartment. The landlord keeps the building safe and the locks working. You decide who gets a key and what you leave on the table.

With Amazon Bedrock, AWS runs the servers that host the models and the service itself. You are still responsible for IAM permissions, the data you send in prompts or use to customize a model, guardrail settings, network paths, logging, and the application code around the model. With Amazon SageMaker, you run notebooks, training jobs, and endpoints yourself, so you set up more things. The more you manage yourself, the more is on your side of the line.

Exam tip: If a question asks who patches the infrastructure under a managed service, the answer is AWS. If it asks who decides which users can call a model, or who classifies the data, the answer is the customer.

Identity and access: IAM

AWS Identity and Access Management (IAM) controls who (a principal) can do what (actions) on which resources. Key ideas:

  • Least privilege: give only the permissions a task needs. An app that only calls a model should be allowed to call that model. It should not be able to manage or delete custom models.
  • Roles over long-lived keys: a role gives temporary credentials to a service, such as a Lambda function or SageMaker job. This way, no access keys sit in your code.
  • Policies: JSON documents attached to identities or resources that allow or deny actions. An explicit deny always wins.
  • Secrets: store database passwords and API keys in AWS Secrets Manager, not in code or prompts.

Worked example: a support chatbot runs in Lambda and calls Bedrock. Give the Lambda execution role permission to call only the approved model, plus read access to the one knowledge base it needs. If an attacker takes over the function, they still cannot touch other models, buckets, or accounts.

Encryption at rest and in transit

StateProtects againstAWS mechanism
At restSomeone reading stored data (S3 objects, training data, model files) without permissionAWS KMS keys, either AWS managed or customer managed
In transitSomeone listening in on or changing data as it travels over the networkTLS on service endpoints

Customer managed KMS keys let you control key policies and key rotation (swapping keys on a schedule). You can also audit and revoke key use. KMS use is logged in CloudTrail, which helps with later audits. Encryption does not replace access control. A user who has permission for both the data and the key can still read the data.

Private network access

By default, calls to AWS service APIs go to public service endpoints over TLS. AWS PrivateLink (interface VPC endpoints) lets resources in your VPC (your private network in AWS) reach services such as Bedrock. The traffic does not cross the public internet, and you do not need an internet gateway. This matters for regulated workloads that must keep traffic on the AWS network. Endpoint policies can also limit what can be called through the endpoint.

Finding sensitive data: Amazon Macie

Amazon Macie uses machine learning and pattern matching to find sensitive data in Amazon S3, such as personally identifiable information (PII). It also reports on how secure your buckets are. Run it on buckets that hold training data, fine-tuning data, or documents for a RAG knowledge base (RAG means the model looks up documents to answer), before the data reaches a model. Macie finds data. It does not remove it. You decide whether to redact (black out), restrict, or delete it.

Privacy for AI is more than scanning S3. Models can memorize or reveal personal data. Prompts may contain customer details. Laws may limit what you can collect or where you can process it. Amazon Bedrock Guardrails can detect sensitive information in prompts and responses and mask or block it. This works alongside scanning of stored data.

Common trap: Macie scans data stored in S3. It does not block prompt injection or filter live model output. Guardrails do that.

Data protection and provenance

You can only trust an AI system if you trust its data. You also need to be able to show where the data came from.

  • Data lineage: a record of where data came from and each change made to it. If a model behaves badly, lineage helps you trace the problem back to a source.
  • Data cataloging: the AWS Glue Data Catalog is a central store of information about your data (metadata). It lists datasets, schemas, and locations, so data is easy to find and manage.
  • Documenting data origins: SageMaker Model Cards record a model's intended use, training data, and evaluation details.
  • Source citation: in RAG apps, have the model cite the documents it used so users can check answers. Bedrock Knowledge Bases can return source attributions.

Threats specific to AI systems

ThreatWhat happensTypical mitigation
Prompt injectionHarmful text in user input or retrieved content overrides the developer's instructionsInput validation, guardrails with prompt attack filters, least-privilege tool access, treating retrieved text as untrusted
JailbreakA carefully written prompt tricks the model into ignoring its safety rulesGuardrails, content filters, testing and red teaming
Data poisoningBad or harmful records are slipped into training or fine-tuning data to make the model misbehaveData integrity controls, source vetting, access control, lineage
Model theftSomeone copies a model's files or copies its behavior without permissionIAM, encryption, network isolation, monitoring for unusual access
Sensitive data leakageThe model or app reveals personal or confidential dataCollect less data, mask data, sensitive information filters, access control on retrieval sources
Hallucination abuseAttackers or careless users take advantage of, or trust, confident but false output, such as made-up facts or package namesGrounding with RAG, citations, human review for high-impact decisions

Exam tip: Prompt injection is a risk in the application itself. Match it to guardrails and input handling, not to encryption or network controls.

Common trap: Prompt injection and jailbreaking are related but not the same. Injection attacks the application's instructions, often through content you do not trust. Jailbreaking attacks the model's built-in safety training.

How Bedrock handles your data

  • Your prompts and completions (the model's replies) are not used to train the base foundation models. They are not shared with model providers.
  • When you fine-tune or continue pretraining, you get a private copy of the base model. Your training data is not used to improve the base model for others. You can encrypt custom models with your KMS key.
  • Data is encrypted in transit and at rest. You can reach Bedrock privately with PrivateLink.

Application security and monitoring

NeedTool
Record who called which API, when, from whereAWS CloudTrail

Think of CloudTrail as a building's door-badge log (who did what). CloudWatch is the dashboard and alarms (how things are running). Invocation logging is the transcript of the conversations with the model. Invocation logs can hold sensitive data too, so encrypt the log destination and limit who can access it.

Key takeaways

  • AWS secures the cloud; you secure your data, access, configuration, and application.
  • Use IAM least privilege with roles, KMS for encryption at rest, TLS in transit, and PrivateLink for private paths.
  • Macie finds sensitive data in S3. Guardrails help filter sensitive data and attacks while the app runs.
  • Lineage, the Glue Data Catalog, model cards, and RAG citations show where data and answers come from.
  • Know the threats: prompt injection, jailbreak, poisoning, theft, leakage, hallucination abuse.
  • Bedrock does not train base models on your data. Monitor with CloudTrail, CloudWatch, invocation logging, and Config.

5.2 Governance and compliance

Why governance matters

Security stops bad things from happening. Governance shows outsiders, again and again, that you have rules and follow them. Regulated industries and customers want proof, not promises. Compliance means meeting outside requirements. Governance is your own system of policies, roles, and reviews that makes compliance possible.

Standards and regulations

ItemWhat it is
ISO standardsInternational standards for how to manage a program, such as information security (ISO/IEC 27001) and AI management (ISO/IEC 42001)
SOC reportsReports from independent auditors on how a service company controls its systems
Algorithm accountability lawsLaws that require organizations to check and explain their automated decision systems, for example for bias and impact
GDPR (light level)EU data protection law for personal data. Its themes include lawful use, people's rights over their data, and limits on sending data across borders

You do not need to know legal details. You only need to know that AI systems fall under such rules and that AWS provides proof of its own compliance.

AWS services for governance

ServiceUseThink of it as
AWS ArtifactDownload AWS compliance reports (SOC, ISO) and agreements when you need themThe library of AWS's audit paperwork
AWS Audit ManagerKeeps collecting evidence of your own usage and matches it to prebuilt or custom frameworks, which makes audits easierThe evidence collector for your audit

Worked example: an auditor asks for proof that your AI workload meets a set of controls. You download AWS's SOC report from Artifact to cover the infrastructure side. You use Audit Manager to gather evidence for your side, Config to show buckets stayed encrypted, and CloudTrail to show who accessed what.

Exam tip: "Download AWS's compliance report" is Artifact. "Collect evidence for an audit of my resources" is Audit Manager. They sound alike, but they cover different parties.

Common trap: Config tracks settings; CloudTrail tracks API calls. A question about a bucket's setting changing over time points to Config. A question about which user made a call points to CloudTrail. Service Quotas is about capacity, not security, but it can matter when you scale up model use.

Data governance strategies

  • Data lifecycles: decide how data is created, used, archived, and deleted. This way, training data is not kept or reused for no reason.
  • Logging: record who accesses and changes data and models, so people are accountable.
  • Residency: keep data in the Regions or countries that laws or contracts require. Pick Regions on purpose and check where the model processes data.
  • Monitoring and observation: watch data quality, access patterns, and model behavior over time. Drift (results getting worse as the world changes) can hurt results.
  • Retention: keep data and logs as long as required, and no longer than needed. Keeping them too long or too short both create risk.

Governance frameworks: Generative AI Security Scoping Matrix

The matrix sorts generative AI use cases by how much of the system you own. This shows which security duties fall to you. The more you own, the more you must govern.

ScopeDescriptionYour ownership
1Consumer app: using a public generative AI serviceLowest
2Enterprise app: using a third-party application with generative AI featuresLow
3Pre-trained models: building an app on an existing foundation modelMedium
4Fine-tuned models: customizing a model with your dataHigh
5Self-trained models: building and training a model from scratchHighest

Exam tip: A higher scope number means more responsibility for you, including governing training data. Using Bedrock with an unchanged foundation model is around scope 3. Fine-tuning moves you to scope 4.

Policies, review, and transparency

  • Policies: written rules for acceptable AI use, data handling, and approving new models and use cases.
  • Review cadence: reviews on a regular schedule, plus extra reviews when a model, data source, or law changes.
  • Review strategies: mix technical checks, such as evaluation and bias testing, with human review by people from security, legal, and the business.
  • Transparency standards: write down how the model works, its data sources, its limits, and its intended use. Model cards help, and so does telling users clearly that they are talking to AI.
  • Team training: people who build or use AI need training on policy, data handling, and risks such as prompt injection and leakage.
  • Following protocols: assign owners, set approval gates, track exceptions, keep evidence, and audit whether people follow the rules.

Key takeaways

  • Artifact gives you AWS's compliance reports. Audit Manager gathers evidence about your usage.
  • Config records settings, CloudTrail records API calls, Inspector scans for weaknesses, and Trusted Advisor gives best-practice checks.
  • Data governance covers lifecycle, logging, residency, monitoring, and retention.
  • The Scoping Matrix runs from scope 1 (consumer app) to scope 5 (self-trained). A higher scope means more responsibility.
  • Good governance needs policies, regular reviews, transparency documentation, training, and processes that are enforced.

Self-check questions

Try to answer first, then reveal and mark yourself. Your score is saved in this browser.

  1. What does AWS secure vs what do you secure (shared responsibility)?

    AWS secures the cloud infrastructure. You secure your data, access, and settings. The split follows who controls each layer.

  2. Which service finds PII in S3?

    Amazon Macie. It uses ML and pattern matching to find sensitive data in S3.

  3. How can traffic to Bedrock avoid the public internet?

    AWS PrivateLink / VPC interface endpoints. They give your VPC a private connection to the service.

  4. Which service downloads SOC and ISO reports?

    AWS Artifact. It is the portal for AWS compliance reports and agreements.

  5. Which service logs who called which API?

    AWS CloudTrail. It keeps a record of API activity for audits.

  6. Which service automates audit evidence collection?

    AWS Audit Manager. It keeps gathering evidence and matches it to compliance frameworks.

  7. What is data lineage?

    A record of where data came from and how it was changed. It helps you trace model problems back to their source.

  8. What is prompt injection, and what kind of risk is it?

    Harmful input that overrides the application's instructions. It is an application security risk for GenAI.

  9. What is the Generative AI Security Scoping Matrix?

    An AWS framework that sorts GenAI use cases into scopes 1 to 5 to show who is responsible for what. Your ownership grows with the scope.

  10. Which service tracks configuration changes against compliance rules?

    AWS Config. It records resource settings and checks them against rules.

  11. A company fine-tunes a model on Bedrock with proprietary data and wants to control the encryption of the resulting custom model. What should it use?

    A customer managed AWS KMS key. KMS gives you control over the key policy, rotation, and audit.

  12. A security team needs a record of prompts and responses sent to Bedrock models for later review. What should they enable?

    Bedrock model invocation logging to S3 or CloudWatch Logs. It is not on by default, and it saves request and response data.

  13. Attackers insert malicious records into a fine-tuning dataset so the model misbehaves. What threat is this, and which control helps most?

    Data poisoning. Data integrity controls, source vetting, and access control help most because they protect the training data.

  14. An auditor wants evidence that S3 buckets holding training data stayed encrypted over the past quarter. Which service helps?

    AWS Config, because it records setting history and checks resources against rules.

  15. A company builds an application on an unmodified foundation model in Bedrock. Roughly which scope of the Security Scoping Matrix is this, and what changes if it fine-tunes?

    Scope 3 (pre-trained models). Fine-tuning moves it to scope 4, which adds responsibility for the training data and the custom model.
