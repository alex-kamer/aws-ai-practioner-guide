This domain is less about memorizing configuration steps and more about knowing which tool answers which question. The exam describes a risk or an audit need and asks you to pick the service. Read each section for the reasoning, then use the tables as a lookup.

5.1 Secure AI systems

Shared responsibility applied to AI

AWS secures the cloud: data centers, hardware, and the infrastructure underneath managed services. You secure what you put in the cloud: your data, who can access it, how services are configured, and how your application behaves. A rental analogy helps: the landlord keeps the building sound and the locks working, but you decide who gets a key and what you leave on the table.

With Amazon Bedrock, AWS operates the model hosting infrastructure and the service itself. You remain responsible for IAM permissions, the data you send in prompts or use for customization, guardrail configuration, network paths, logging, and the application code around the model. With Amazon SageMaker, where you run notebooks, training jobs, and endpoints, you own more of the configuration surface. The more you manage yourself, the more falls on your side of the line.

Exam tip: If a question asks who is responsible for patching the underlying infrastructure of a managed service, the answer is AWS. If it asks who decides which users may invoke a model or who classifies the data, the answer is the customer.

Identity and access: IAM

AWS Identity and Access Management controls who (a principal) can do what (actions) on which resources. Key ideas:

  • Least privilege: grant only the permissions a task needs. An application that only calls a model should be allowed to invoke that model, not to manage or delete custom models.
  • Roles over long-lived keys: a role gives temporary credentials to a service, such as a Lambda function or SageMaker job, so no access keys are embedded in code.
  • Policies: JSON documents attached to identities or resources that allow or deny actions. An explicit deny always wins.
  • Secrets: keep database passwords and API keys in AWS Secrets Manager rather than in code or prompts.

Worked example: a support chatbot runs in Lambda and calls Bedrock. Give the Lambda execution role permission to invoke only the approved model, plus read access to the one knowledge base it needs. If the function is compromised, the attacker cannot touch other models, buckets, or accounts.

Encryption at rest and in transit

StateProtects againstAWS mechanism
At restSomeone reading stored data (S3 objects, training data, model artifacts) without authorizationAWS KMS keys, either AWS managed or customer managed
In transitInterception or tampering on the networkTLS on service endpoints

Customer managed KMS keys give you control over key policies, rotation, and the ability to audit and revoke key use. KMS usage is logged in CloudTrail, which supports later audits. Encryption does not replace access control: a user with permission to both the data and the key can still read it.

Private network access

By default, calls to AWS service APIs go to public service endpoints over TLS. AWS PrivateLink (interface VPC endpoints) lets resources in your VPC reach services such as Bedrock without sending traffic over the public internet or needing an internet gateway. This matters for regulated workloads that require traffic to stay on the AWS network. Endpoint policies can further limit what can be called through the endpoint.

Finding sensitive data: Amazon Macie

Amazon Macie uses machine learning and pattern matching to discover sensitive data, such as personally identifiable information, in Amazon S3 and to report on bucket security posture. Run it against buckets that hold training data, fine-tuning datasets, or documents for a RAG knowledge base before the data reaches a model. Macie finds data; it does not by itself remove it. You decide whether to redact, restrict, or delete.

Privacy concerns for AI go beyond S3 scanning. Models can memorize or reveal personal data, prompts may contain customer details, and regulations may limit what you can collect or where you can process it. Amazon Bedrock Guardrails can detect and mask or block sensitive information in prompts and responses, which complements scanning of stored data.

Common trap: Macie scans S3 data at rest. It is not the tool that blocks prompt injection or filters live model output. Guardrails handle that.

Data protection and provenance

Trustworthy AI needs trustworthy data, and you must be able to show where it came from.

  • Data lineage: a record of where data originated and each transformation applied. If a model behaves badly, lineage lets you trace the cause back to a source.
  • Data cataloging: the AWS Glue Data Catalog is a central metadata store describing datasets, schemas, and locations, which makes data discoverable and governable.
  • Documenting data origins: SageMaker Model Cards record intended use, training data, and evaluation details for a model.
  • Source citation: in RAG applications, have the model cite the retrieved documents so users can verify answers. Bedrock Knowledge Bases can return source attributions.

Threats specific to AI systems

ThreatWhat happensTypical mitigation
Prompt injectionMalicious text in user input or retrieved content overrides the developer's instructionsInput validation, guardrails with prompt attack filters, least-privilege tool access, treating retrieved text as untrusted
JailbreakA crafted prompt persuades the model to ignore its safety rulesGuardrails, content filters, testing and red teaming
Data poisoningBad or malicious records are inserted into training or fine-tuning data to corrupt behaviorData integrity controls, source vetting, access control, lineage
Model theftUnauthorized copying or extraction of model artifacts or behaviorIAM, encryption, network isolation, monitoring for unusual access

Hallucination abuseAttackers or careless users exploit or rely on confident but false output, for example fabricated facts or package namesGrounding with RAG, citations, human review for high-impact decisions

Exam tip: Prompt injection is an application-layer risk. Match it to guardrails and input handling, not to encryption or network controls.

Common trap: Prompt injection and jailbreaking are related but not identical. Injection targets the application's instructions, often through untrusted content. Jailbreaking targets the model's safety training.

How Bedrock handles your data

  • Prompts and completions are not used to train the base foundation models, and are not shared with model providers.
  • When you fine-tune or continue pretraining, you get a private copy of the base model; your training data is not used to improve the base model for others. Custom models can be encrypted with your KMS key.
  • Data is encrypted in transit and at rest, and you can reach Bedrock privately with PrivateLink.

Application security and monitoring

Think of CloudTrail as the building's door-badge log (who did what), CloudWatch as the dashboard and alarms (how things are running), and invocation logging as the transcript of the conversations with the model. Invocation logs may contain sensitive data themselves, so encrypt and restrict access to the log destination.

Key takeaways

  • AWS secures the cloud; you secure your data, access, configuration, and application.
  • Use IAM least privilege with roles, KMS for encryption at rest, TLS in transit, PrivateLink for private paths.
  • Macie finds sensitive data in S3; Guardrails help filter sensitive data and attacks at runtime.
  • Lineage, the Glue Data Catalog, model cards, and RAG citations document where data and answers come from.
  • Know the threats: prompt injection, jailbreak, poisoning, theft, leakage, hallucination abuse.
  • Bedrock does not train base models on your data; monitor with CloudTrail, CloudWatch, invocation logging, and Config.

5.2 Governance and compliance

Why governance matters

Security stops bad things from happening. Governance proves, repeatedly and to outsiders, that you have rules and follow them. Regulated industries and customers want evidence, not promises. Compliance means meeting external requirements; governance is the internal system of policies, roles, and reviews that makes compliance achievable.

Standards and regulations

ItemWhat it is
ISO standardsInternational standards for management systems, such as information security (ISO/IEC 27001) and AI management systems (ISO/IEC 42001)
SOC reportsIndependent audit reports on a service organization's controls
Algorithm accountability lawsLaws that require organizations to assess and explain automated decision systems, for example for bias and impact
GDPR (light level)EU data protection regulation covering personal data, with themes such as lawful use, data subject rights, and limits on cross-border transfer

You are not expected to know legal detail, only that AI systems are subject to such rules and that AWS provides evidence of its own compliance.

Worked example: an auditor asks for proof that your AI workload meets a control framework. You download AWS's SOC report from Artifact to cover the infrastructure side. You use Audit Manager to gather evidence for your side, Config to show buckets stayed encrypted, and CloudTrail to show who accessed what.

Exam tip: "Download AWS's compliance report" is Artifact. "Collect evidence for an audit of my resources" is Audit Manager. They sound alike but cover different parties.

Common trap: Config tracks configuration state; CloudTrail tracks API calls. A question about a bucket's setting changing over time points to Config. A question about which user made the call points to CloudTrail. Quota awareness (Service Quotas) is about capacity, not security, but can matter when scaling model usage.

Data governance strategies

  • Data lifecycles: define how data is created, used, archived, and deleted, so training data is not kept or reused without purpose.
  • Logging: record access and changes to data and models for accountability.
  • Residency: keep data in the Regions or countries that laws or contracts require. Choose Regions deliberately and check where model processing happens.
  • Monitoring and observation: watch data quality, access patterns, and model behavior over time, since drift can degrade results.
  • Retention: keep data and logs as long as required, and no longer than needed; both over- and under-retention create risk.

Governance frameworks: Generative AI Security Scoping Matrix

The matrix classifies generative AI use cases by how much of the stack you own, so you can see which security responsibilities shift to you. The more ownership, the more you must govern.

ScopeDescriptionYour ownership
1Consumer app: using a public generative AI serviceLowest
2Enterprise app: using a third-party application with generative AI featuresLow
3Pre-trained models: building an app on an existing foundation modelMedium
4Fine-tuned models: customizing a model with your dataHigh
5Self-trained models: building and training a model from scratchHighest

Exam tip: Higher scope number means more responsibility for you, including governance of training data. Using Bedrock with a foundation model unchanged is around scope 3; fine-tuning moves you to scope 4.

Policies, review, and transparency

  • Policies: written rules for acceptable AI use, data handling, and approval of new models and use cases.
  • Review cadence: scheduled reviews (for example periodic) plus event-driven reviews when a model, data source, or regulation changes.
  • Review strategies: combine technical checks, such as evaluation and bias testing, with human and cross-functional review by security, legal, and business owners.
  • Transparency standards: document how the model works, its data sources, limits, and intended use. Model cards and clear disclosure to users that they are interacting with AI support this.
  • Team training: staff who build or use AI need training on policy, data handling, and risks such as prompt injection and leakage.
  • Following protocols: assign owners, define approval gates, track exceptions, keep evidence, and audit adherence.

Key takeaways

  • Artifact gives AWS's compliance reports; Audit Manager gathers evidence about your usage.
  • Config records configuration, CloudTrail records API calls, Inspector scans for vulnerabilities, Trusted Advisor gives best-practice checks.
  • Data governance covers lifecycle, logging, residency, monitoring, and retention.
  • The Scoping Matrix runs from scope 1 (consumer app) to scope 5 (self-trained); higher scope means more responsibility.
  • Good governance needs policies, regular reviews, transparency documentation, training, and enforced processes.

Self-check questions

Try to answer first, then reveal and mark yourself. Your score is saved in this browser.

  1. What does AWS secure vs what do you secure (shared responsibility)?

    AWS secures the cloud infrastructure; you secure your data, access management, and configuration. The split follows who controls each layer.

  2. Which service finds PII in S3?

    Amazon Macie. It uses ML and pattern matching to discover sensitive data in S3.

  3. How can traffic to Bedrock avoid the public internet?

    AWS PrivateLink / VPC interface endpoints. They provide private connectivity from your VPC to the service.

  4. Which service downloads SOC and ISO reports?

    AWS Artifact. It is the portal for AWS compliance reports and agreements.

  5. Which service logs who called which API?

    AWS CloudTrail. It records API activity as an audit trail.

  6. Which service automates audit evidence collection?

    AWS Audit Manager. It continuously gathers evidence mapped to compliance frameworks.

  7. What is data lineage?

    A record of where data came from and how it has been transformed. It lets you trace model problems back to their source.

  8. What is prompt injection, and what kind of risk is it?

    Malicious input that overrides the application's instructions; it is an application security risk for GenAI.

  9. What is the Generative AI Security Scoping Matrix?

    An AWS framework that classifies GenAI use cases into scopes 1 to 5 to clarify security responsibilities, since ownership grows with scope.

  10. Which service tracks configuration changes against compliance rules?

    AWS Config. It records resource configuration and evaluates it against rules.

  11. A company fine-tunes a model on Bedrock with proprietary data and wants to control the encryption of the resulting custom model. What should it use?

    A customer managed AWS KMS key; KMS gives control over key policy, rotation, and audit.

  12. A security team needs a record of prompts and responses sent to Bedrock models for later review. What should they enable?

    Bedrock model invocation logging to S3 or CloudWatch Logs; it is not on by default and captures request and response data.

  13. Attackers insert malicious records into a fine-tuning dataset so the model misbehaves. What threat is this, and which control helps most?

    Data poisoning; data integrity controls, source vetting, and access control reduce it because they protect the training data.

  14. An auditor wants evidence that S3 buckets holding training data stayed encrypted over the past quarter. Which service helps?

    AWS Config, because it records configuration history and evaluates resources against rules.

  15. A company builds an application on an unmodified foundation model in Bedrock. Roughly which scope of the Security Scoping Matrix is this, and what changes if it fine-tunes?

    Scope 3 (pre-trained models); fine-tuning moves it to scope 4, adding responsibility for the training data and the custom model.
