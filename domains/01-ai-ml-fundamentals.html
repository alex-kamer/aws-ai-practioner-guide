1.1 Explain basic AI concepts and terminologies

The AI / ML / deep learning / generative AI hierarchy

These terms fit inside each other like Russian dolls. Artificial intelligence (AI) is the widest term. It means any technique that lets a machine do tasks we link to human intelligence. That includes hand-written rule systems. An expert system with thousands of if/then rules is AI. Machine learning (ML) is the part of AI where nobody gives the system the rules. It works them out from examples. Deep learning (DL) is the part of ML that uses neural networks (models made of many layers). These layers can learn useful features straight from raw pixels, audio, or text. A person does not have to design those features by hand. Generative AI (GenAI) is deep learning used to create new content, such as text, images, code, or audio. It does more than predict a label or number. Most GenAI today is built on foundation models. These are very large models trained first on broad data and then adapted to many tasks.

Analogy: a traditional program is a recipe you write. ML is a chef who tastes thousands of dishes and works out the recipe. Deep learning is a chef who also figures out which flavors matter without being told. Generative AI is that chef inventing a brand new dish.

LayerKey ideaExample
AIMachines doing "intelligent" tasks, by any methodRule-based chess engine
MLLearns patterns from dataChurn prediction with gradient-boosted trees
Deep learningMulti-layer neural networks learn features automaticallyImage classification, speech recognition
Generative AIProduces new content from learned distributionsLLM drafting an email

Core terminology

  • Algorithm: the step-by-step method used to learn (for example linear regression, decision tree, k-means, neural network training). It is the method, not the result.
  • Model: what you get after you run an algorithm on data. It holds the learned values (parameters) and the structure that uses them. You deploy a model, not an algorithm.
  • Training: adjusting the model's parameters to cut its errors on the training data. Inference: using the trained model to make predictions on new data. Training is costly and happens now and then. Inference happens all the time in production.
  • Features and labels: features are the inputs (square footage, age of house). The label (target) is what you want to predict (sale price). Supervised learning needs labels.
  • Bias (in data/models): unfair results that repeat in a pattern. One example is a hiring model trained on past decisions that favored one group. Do not mix it up with statistical bias in the bias/variance tradeoff, covered below.
  • Fairness: the model should not give worse results to some groups than to others. To measure it, you compare performance across groups.
  • Fit: how well the model captures the real pattern: underfit, good fit, or overfit.
  • NLP (natural language processing): understanding and writing human language (sentiment, translation, entity extraction). Computer vision: understanding images and video (object detection, face analysis, OCR). LLM (large language model): a very large neural network trained on text to guess the next word (token). This gives it broad language skills.

See the glossary for short definitions.

Learning types in depth

TypeDataGoalExamples

Semi-supervisedSmall labeled set plus large unlabeled setUse cheap unlabeled data to boost a model trained on scarce labelsClassify medical scans when only a few are expert-labeled

Supervised learning is like studying with an answer key. Classification predicts a category (binary: fraud / not fraud; multiclass: which product category). Regression predicts a continuous number (delivery time, revenue). The same family of algorithms often does both. The only difference is the type of label.

Unsupervised learning is like sorting a pile of unlabeled photos into piles that look alike. Clustering groups similar items (customer segments). Dimensionality reduction squeezes many features into fewer ones while keeping most of the information. It helps with visualization and with dropping repeated inputs. Anomaly detection flags points that differ from the normal pattern, such as odd server behavior. It often works without any labeled examples of failures.

Self-supervised learning is worth a closer look because it powers GenAI. Take a sentence, hide the last word, and ask the model to guess it. The "label" comes free from the text itself, so you can train on huge piles of unlabeled text. The pre-trained model is then adapted to specific tasks. Reinforcement learning has an agent take actions, get rewards or penalties, and learn a policy (a set of rules for what to do). In RLHF (reinforcement learning from human feedback), people rate which answers they prefer. Those ratings become the reward that steers an LLM toward what people want.

Exam tip: Keywords in a scenario point to the learning type. "Historical labeled examples" means supervised. "Group customers with no predefined categories" means unsupervised clustering. "Agent learns through trial and error and rewards" means reinforcement. "Predict the next word from unlabeled text" means self-supervised.

Common trap: Anomaly detection and classification look alike. If you have labeled examples of fraud, it is supervised classification. If you only know what normal looks like, it is unsupervised anomaly detection. Also, clustering finds groups on its own. It does not predict pre-defined categories.

Data types and data quality

Data is labeled (has the answer attached) or unlabeled. It is also structured (rows and columns in a database), semi-structured (JSON, XML), or unstructured (free text, images, audio, video). Common ML data shapes are tabular, time-series (observations in time order, so you must not shuffle them across time), image, and text.

The rule is "garbage in, garbage out." A model can never be better than its data. Watch for:

  • Missing values and noise: fill them in (impute), remove them, or clean them.
  • Too little or unrepresentative data: a model trained mostly on one group of people does poorly on others (a source of bias).
  • Class imbalance: very few examples of the rare class (fraud). Simple models then tend to ignore it.
  • Wrong or inconsistent labels: the model learns your mistakes exactly.
  • Data leakage: information from the future or from the label slips into the features. Test scores look great, but the model fails in production.

Training, validation, and test sets

Splitting data keeps you from fooling yourself. Think of an exam. The training set is the textbook the model studies. The validation set is the practice exam. You use it to adjust the study plan (tune hyperparameters, pick between models). The test set is the final exam. You use it once, to get an honest estimate of real-world performance. A typical split is about 70/15/15 or 80/10/10. If you tune against the test set, it no longer gives an honest score.

Fit: overfitting, underfitting, and the bias/variance tradeoff

Imagine drawing a curve through scattered points. A straight line through curved data misses the pattern (underfitting). A wiggly line through every point memorizes the noise (overfitting). The goal is a model that works well on new data it has not seen.

UnderfittingGood fitOverfitting
Training errorHighLowVery low
Validation/test errorHighLowHigh
Statistical issueHigh biasBalancedHigh variance
FixesMore complex model, better features, train longerMore data, simpler model, regularization, early stopping, drop irrelevant features

Bias here means error from assumptions that are too simple. Variance means the model is too sensitive to the quirks of its particular training set. Lowering one tends to raise the other. That is the tradeoff. Remember this check: a big gap between training and test performance means overfitting. Poor performance on both means underfitting.

In SageMaker, real-time inference uses an endpoint that stays running. Batch transform runs a job over a dataset in Amazon S3 and writes the results back.

Exam tip: If the scenario says "large volume, no immediate response needed, minimize cost," choose batch. If it says "user is waiting" or "decision at transaction time," choose real-time.

Common trap: Do not mix up the two meanings of "bias." One is unfairness in data or outcomes (fixed with SageMaker Clarify and better data). The other is underfitting error (fixed with a more flexible model). The context tells you which one is meant.

Key takeaways

  • AI > ML > deep learning > generative AI, each a subset of the previous.
  • The algorithm is the method. The model is the trained result. Inference is using it.
  • Match the learning type to the data: labeled, unlabeled, few labels, self-made labels, or rewards.
  • Training teaches, validation picks, and test judges. Never tune on the test set.
  • Overfit means low training error and high test error. Underfit means high error on both.

1.2 Identify practical use cases for AI

When AI/ML is the right tool

ML is worth its cost in three cases. The rules are too many or too fuzzy to write by hand. The patterns hide in large amounts of data. Or decisions must happen at a scale people cannot match. Typical wins: automating repeated judgments (routing support tickets), helping human experts (flagging suspicious scans for a radiologist), finding patterns in huge datasets, and personalizing at scale.

It is a poor fit when you need a specific, deterministic outcome (the same exact answer every time). A tax calculation or an eligibility check set by law must be correct every time, so write code or rules. ML outputs are probabilistic (based on likelihood) and can be wrong. It is also a poor fit when the cost is bigger than the benefit, when you have too little quality data (or none), or when errors are costly or hard to explain and no human reviews them.

Worked example: a retailer wants to apply a fixed 8% sales tax. That is simple arithmetic, so no ML. The same retailer wants to forecast next month's demand for each product from three years of sales. That is a pattern-in-data problem, so ML fits.

Real-world uses include: computer vision (inspection, moderation), NLP (sentiment, summarization), speech recognition, recommendation systems, fraud detection, forecasting, and conversational interfaces.

Key takeaways

  • Use ML for fuzzy, data-rich problems that need to scale. Use plain code for exact, fixed-answer problems.
  • A number means regression, a category means classification, and unlabeled groups mean clustering.
  • Pick a managed AI service when it fits the task. Use SageMaker for custom needs.

1.3 Describe the ML development lifecycle

The pipeline, stage by stage

Define problem -> Collect data -> EDA -> Pre-process -> Feature engineering -> Train
   -> Tune hyperparameters -> Evaluate -> Deploy -> Monitor -> (retrain)

This is a loop, not a straight line. Monitoring in production often sends you back to collect more data and retrain.

  • Define the problem and success metric: is it classification or regression, and what business result matters?
  • Collect data: from databases, logs, S3, or streams. People may need to add labels.
  • Exploratory data analysis (EDA): before modeling, look at how values are spread, missing values, outliers, correlations, and class balance.
  • Pre-process: clean, fill gaps (impute), remove duplicates, normalize or scale values, encode categories, and split into train/validation/test.
  • Feature engineering: create or pick inputs that make the pattern easier to learn (for example, get "day of week" from a timestamp).
  • Train: run the algorithm to fit the parameters.
  • Tune hyperparameters: adjust the settings you choose before training.
  • Evaluate: measure on held-out data against the chosen metrics, including business metrics.
  • Deploy: make the model available for real-time or batch inference.
  • Monitor: watch for drift (the data changing over time) and falling quality, then retrain.

Hyperparameters vs parameters

Parameters (weights) are learned from data during training. Hyperparameters (learning rate, number of trees, number of layers, batch size, epochs) are settings you pick before training. They control how learning goes. Tuning is a search: try combinations, compare validation scores, and keep the best. It is like changing the oven temperature and baking time across several test batches. SageMaker automatic model tuning does this search for you.

Model sources and production hosting

Open-source pre-trained models (for example from JumpStart or public hubs) are quick and cheap to start with, and you can fine-tune them. Custom-trained models give you the most control and fit your data best, but they cost more time, data, and skill. Models from managed services (such as those in Bedrock) need no training at all.

For production, a managed API service (a SageMaker endpoint or Bedrock) means less work to run. AWS handles scaling and infrastructure. A self-hosted API on your own compute gives you more control over the setup and cost. But you own patching, scaling, and uptime.

MLOps

MLOps brings DevOps habits to ML. That means tracking experiments, repeatable and automated pipelines, scalable infrastructure, managing technical debt (hidden data dependencies, ad-hoc notebooks), production-readiness checks, constant monitoring, and retraining. It matters because a model is not done once it is deployed. Real-world data changes over time (drift), so performance drops. And a one-off notebook cannot be reliably re-run or audited. On AWS, the usual answer is Pipelines plus Model Registry plus Model Monitor.

Exam tip: Match the tool to the verb. Label means Ground Truth. Prepare or transform means Data Wrangler. Share features means Feature Store. Detect bias or explain means Clarify. No-code means Canvas. AutoML means Autopilot. Pre-trained starting point means JumpStart. Version or approve means Model Registry. Orchestrate means Pipelines. Detect drift means Model Monitor.

Common trap: Clarify (bias and explainability) is not Model Monitor (drift), though Clarify can also feed bias monitoring. Data Wrangler prepares data, while Feature Store keeps finished features. Ground Truth labels data and does not train models. Hyperparameters are not learned parameters.

Evaluating models: the confusion matrix and metrics

For classification, count the outcomes in a confusion matrix: true positives (TP), false positives (FP), false negatives (FN), and true negatives (TN).

Worked example: a fraud model scores 1,000 transactions, and 50 of them are really fraud. It catches 40 (TP = 40), misses 10 (FN = 10), wrongly flags 20 legitimate ones (FP = 20), and correctly clears 930 (TN = 930).

Predicted fraudPredicted legit
Actually fraudTP = 40FN = 10
Actually legitFP = 20TN = 930
MetricFormulaResultAnswers
Accuracy(TP+TN) / total970/1000 = 97%How often is it right overall?
PrecisionTP / (TP+FP)40/60 = 66.7%Of flagged items, how many were truly fraud?
Recall (sensitivity)TP / (TP+FN)40/50 = 80%Of real fraud, how much did we catch?
F12 x P x R / (P+R)about 0.73Single balance of precision and recall

Notice that accuracy looks great at 97%. Yet a model that always said "legit" would score 95% and catch zero fraud. That is why accuracy can mislead when classes are imbalanced. Choose by the cost of each kind of error. When missing a positive is costly (cancer screening, fraud), favor recall. When false alarms are costly (blocking good customers, or a spam filter that hides real mail), favor precision.

AUC-ROC plots the true-positive rate against the false-positive rate at every decision threshold (the cutoff score for calling something positive). The area under the curve shows how well the model separates the classes, whatever the threshold. 1.0 is perfect, and 0.5 is no better than random guessing.

Regression metrics measure the size of numeric errors. MAE (mean absolute error) is the average size of the errors, in the same units as the target. RMSE (root mean squared error) squares the errors before averaging, so big misses count for more. Lower is better for both.

Business metrics link the model to value: ROI, cost per user, build and running cost, customer feedback or satisfaction, and revenue or conversion impact. A model with a great F1 that costs more than it saves is still a failure.

Exam tip: Questions on rare events (fraud, defects, disease) are really asking "do you know accuracy is misleading?" Pick precision, recall, F1, or AUC. If a question names MAE or RMSE, the problem is regression.

Common trap: Precision and recall are easy to swap. Precision looks at what the model flagged (FP is in the denominator). Recall looks at what is truly there (FN is in the denominator). Also, AUC-ROC and F1 are for classification, never for predicting a number.

Key takeaways

  • The lifecycle is a loop: data, EDA, pre-process, features, train, tune, evaluate, deploy, monitor, retrain.
  • You set hyperparameters. The model learns parameters.
  • Know the one job of each SageMaker tool.
  • Pre-trained and managed options save effort. Custom models give you control.
  • With imbalanced classes, use precision, recall, F1, or AUC. For regression, use MAE or RMSE. Always add business metrics.

Self-check questions

Try to answer first, then reveal and mark yourself. Your score is saved in this browser.

  1. What is the relationship between AI, ML, and deep learning?

    AI is the widest. ML is a part of AI, and deep learning is a part of ML. Each one is a narrower way to get smart behavior.

  2. Which learning type uses labeled data? Which finds clusters?

    Supervised learning uses labeled data. Unsupervised learning (clustering) finds groups. Clustering needs no labels because it finds the structure itself.

  3. An LLM is pre-trained by predicting the next word in huge amounts of unlabeled text. Which learning type is this?

    Self-supervised learning. The labels (the next words) come from the data itself.

  4. When is batch inference better than real-time?

    When you do not need results right away and can process large amounts offline. This costs less than keeping an endpoint running.

  5. A company needs to compute exact sales tax from a fixed legal rate. Should it use ML?

    No. Use rules or code for an exact, fixed outcome, because ML predictions are based on likelihood.

  6. Which technique predicts a continuous number? Which predicts a category?

    Regression predicts a number. Classification predicts a category. The difference is the type of label.

  7. A model scores 99% on training data but 70% on test data. What is the problem and one fix?

    Overfitting (high variance). Fixes include more data, a simpler model, or regularization.

  8. A company wants to extract fields and tables from thousands of scanned invoices. Which service?

    Amazon Textract, because it extracts text, forms, and tables from documents.

  9. A company wants to turn recorded customer calls into text and then detect the sentiment. Which services?

    Amazon Transcribe for speech to text, then Amazon Comprehend for sentiment analysis.

  10. A team wants analysts with no coding skills to build an ML model from a spreadsheet. Which SageMaker capability?

    SageMaker Canvas, which provides visual, no-code model building.

  11. A company wants to check training data and a model for bias and explain predictions. Which SageMaker feature?

    SageMaker Clarify, which detects bias and provides explainability.

  12. Which SageMaker feature detects drift in a deployed model?

    SageMaker Model Monitor, which watches production data and model quality against a baseline.

  13. A fraud model reports 98% accuracy, but only 1% of transactions are fraud. Why might it still be poor, and what should you check?

    It may just say "not fraud" every time. Check precision, recall, F1, or AUC-ROC instead.

  14. Missing a disease case is far worse than a false alarm. Which metric should you prioritize?

    Recall, because it measures the share of true positives caught (it counts false negatives against the model).

  15. Name one technical metric for regression and one business metric for any ML model.

    Technical: MAE or RMSE. Business: ROI or cost per user. These show whether the model is worth it.
