1.1 Explain basic AI concepts and terminologies

The AI / ML / deep learning / generative AI hierarchy

These terms are nested like Russian dolls. Artificial intelligence (AI) is the widest term: any technique that lets a machine perform tasks we associate with human intelligence. That includes hand-written rule systems (an expert system with thousands of if/then rules is AI). Machine learning (ML) is the subset of AI where the system is not given the rules; it infers them from examples. Deep learning (DL) is the subset of ML that uses neural networks with many layers, which can learn useful features directly from raw pixels, audio, or text instead of relying on a human to hand-craft them. Generative AI (GenAI) is deep learning applied to creating new content (text, images, code, audio) rather than only predicting a label or number. Most GenAI today is built on foundation models, very large models pre-trained on broad data and adapted to many tasks.

Analogy: a traditional program is a recipe you write; ML is a chef who tastes thousands of dishes and works out the recipe; deep learning is a chef who also figures out which flavors matter without being told; generative AI is that chef inventing a brand new dish.

LayerKey ideaExample
AIMachines doing "intelligent" tasks, by any methodRule-based chess engine
MLLearns patterns from dataChurn prediction with gradient-boosted trees
Deep learningMulti-layer neural networks learn features automaticallyImage classification, speech recognition
Generative AIProduces new content from learned distributionsLLM drafting an email

Core terminology

  • Algorithm: the learning procedure (for example linear regression, decision tree, k-means, neural network training). It is the method, not the result.
  • Model: the artifact produced when an algorithm is run on data: the learned parameters plus the structure that uses them. You deploy a model, not an algorithm.
  • Training: the process of adjusting model parameters to reduce error on training data. Inference: using the trained model to make predictions on new data. Training is expensive and occasional; inference happens continuously in production.
  • Features and labels: features are the input variables (square footage, age of house); the label (target) is what you want to predict (sale price). Supervised learning needs labels.
  • Bias (in data/models): systematic unfairness, such as a hiring model trained on historical decisions that favored one group. Do not confuse it with the statistical bias in the bias/variance tradeoff, covered below.
  • Fairness: the model should not produce systematically worse outcomes for particular groups. Measuring it requires comparing performance across groups.
  • Fit: how well the model captures the real pattern: underfit, good fit, or overfit.
  • NLP (natural language processing): understanding and generating human language (sentiment, translation, entity extraction). Computer vision: understanding images and video (object detection, face analysis, OCR). LLM (large language model): a very large neural network trained on text to predict the next token, which gives it broad language ability.

See the glossary for short definitions.

Learning types in depth

Supervised learning is like studying with an answer key. Classification predicts a category (binary: fraud / not fraud; multiclass: which product category). Regression predicts a continuous number (delivery time, revenue). The same algorithm family often serves both; what differs is the type of label.

Unsupervised learning is sorting a pile of unlabeled photos into piles that look alike. Clustering groups similar items (customer segments). Dimensionality reduction compresses many features into fewer while keeping most of the information, useful for visualization and for removing redundant inputs. Anomaly detection flags points that differ from the normal pattern, such as unusual server behavior, often without any labeled examples of failures.

Self-supervised learning deserves care because it powers GenAI. Take a sentence, hide the last word, and ask the model to predict it. The "label" comes free from the text itself, so you can train on enormous unlabeled corpora. The pre-trained model is then adapted to specific tasks. Reinforcement learning has an agent take actions, receive rewards or penalties, and learn a policy. In RLHF (reinforcement learning from human feedback), human preference ratings define the reward used to align an LLM with what people want.

Exam tip: Scenario keywords map directly to learning type: "historical labeled examples" means supervised; "group customers with no predefined categories" means unsupervised clustering; "agent learns through trial and error and rewards" means reinforcement; "predict the next word from unlabeled text" means self-supervised.

Common trap: Anomaly detection and classification look similar. If you have labeled examples of fraud, it is supervised classification; if you only know what normal looks like, it is unsupervised anomaly detection. Also, clustering assigns groups it discovers; it does not predict pre-defined categories.

Data types and data quality

Data is labeled (has the answer attached) or unlabeled. It is also structured (rows and columns in a database), semi-structured (JSON, XML), or unstructured (free text, images, audio, video). Common ML shapes are tabular, time-series (ordered observations, where order matters and you must not shuffle across time), image, and text.

The rule is "garbage in, garbage out": model quality is capped by data quality. Watch for:

  • Missing values and noise: must be imputed, removed, or cleaned.
  • Insufficient or unrepresentative data: a model trained mostly on one population performs poorly on others (a source of bias).
  • Class imbalance: very few examples of the rare class (fraud), which makes naive models ignore it.
  • Incorrect or inconsistent labels: the model faithfully learns your mistakes.
  • Data leakage: information from the future or from the label slips into features, producing great test scores and failure in production.

Training, validation, and test sets

Splitting data guards against fooling yourself. Think of an exam: the training set is the textbook the model studies, the validation set is the practice exam used to adjust the study plan (tune hyperparameters, choose between models), and the test set is the final exam, touched once for an honest estimate of real-world performance. A typical split is roughly 70/15/15 or 80/10/10. If you tune against the test set it stops being an honest measure.

Fit: overfitting, underfitting, and the bias/variance tradeoff

Imagine fitting a curve to scattered points. A straight line through curved data misses the pattern (underfitting). A wiggly line through every point memorizes the noise (overfitting). The goal is a model that generalizes to unseen data.

UnderfittingGood fitOverfitting
Training errorHighLowVery low
Validation/test errorHighLowHigh
Statistical issueHigh biasBalancedHigh variance
FixesMore complex model, better features, train longerMore data, simpler model, regularization, early stopping, drop irrelevant features

Bias here means error from overly simple assumptions; variance means sensitivity to the quirks of the particular training set. Lowering one tends to raise the other, which is the tradeoff. The diagnostic pattern to remember: a big gap between training and test performance signals overfitting; poor performance on both signals underfitting.

Inference: batch vs real-time

In SageMaker, real-time inference uses a persistent endpoint, while batch transform runs a job over a dataset in Amazon S3 and writes results back.

Exam tip: If the scenario says "large volume, no immediate response needed, minimize cost," choose batch. If it says "user is waiting" or "decision at transaction time," choose real-time.

Common trap: Do not mix up the two meanings of "bias": unfairness in data/outcomes (addressed with SageMaker Clarify and better data) versus underfitting error (addressed with a more expressive model). The context tells you which.

Key takeaways

  • AI > ML > deep learning > generative AI, each a subset of the previous.
  • Algorithm is the method; model is the trained result; inference is using it.
  • Match learning type to data: labeled, unlabeled, few labels, self-generated labels, or rewards.
  • Train tunes, validation selects, test judges. Never tune on test.
  • Overfit means low training error and high test error; underfit means high error on both.

1.2 Identify practical use cases for AI

When AI/ML is the right tool

ML earns its cost when the rules are too numerous or fuzzy to write by hand, when patterns live in large volumes of data, or when decisions must scale beyond human capacity. Typical wins: automating repetitive judgments (routing support tickets), assisting human experts (flagging suspicious scans for a radiologist), finding patterns in huge datasets, and personalizing at scale.

It is a poor fit when a specific, deterministic outcome is required. A tax calculation or an eligibility check defined by law must give the exact same correct answer every time, so write code or rules. ML outputs are probabilistic and can be wrong. It is also a poor fit when the cost outweighs the benefit, when there is too little (or no) quality data, or when you cannot tolerate or explain errors in a high-stakes setting without human review.

Worked example: a retailer wants to apply a fixed 8% sales tax. That is arithmetic: no ML. The same retailer wants to forecast next month's demand per product from three years of sales: that is a pattern-in-data problem, so ML fits.

Real-world application areas: computer vision (inspection, moderation), NLP (sentiment, summarization), speech recognition, recommendation systems, fraud detection, forecasting, and conversational interfaces.

Key takeaways

  • Use ML for fuzzy, data-rich, scalable problems; use code for deterministic ones.
  • Number means regression, category means classification, unlabeled groups means clustering.
  • Prefer a managed AI service when it matches the task; use SageMaker for custom needs.

1.3 Describe the ML development lifecycle

The pipeline, stage by stage

Define problem -> Collect data -> EDA -> Pre-process -> Feature engineering -> Train
   -> Tune hyperparameters -> Evaluate -> Deploy -> Monitor -> (retrain)

This is a loop, not a line. Monitoring in production often sends you back to data collection and retraining.

  • Define the problem and success metric: is it classification or regression, and what business outcome matters?
  • Collect data: from databases, logs, S3, streams. Labels may need human annotation.
  • Exploratory data analysis (EDA): look at distributions, missing values, outliers, correlations, and class balance before modeling.
  • Pre-process: clean, impute, deduplicate, normalize or scale, encode categories, split into train/validation/test.
  • Feature engineering: create or select inputs that make the pattern easier to learn (for example derive "day of week" from a timestamp).
  • Train: run the algorithm to fit the parameters.
  • Tune hyperparameters: adjust settings you choose before training.
  • Evaluate: measure on held-out data against the chosen metrics, including business metrics.
  • Deploy: expose the model for real-time or batch inference.
  • Monitor: watch for drift and quality decay, then retrain.

Hyperparameters vs parameters

Parameters (weights) are learned from data during training. Hyperparameters (learning rate, number of trees, number of layers, batch size, epochs) are set by you before training and control how learning proceeds. Tuning is a search: try combinations, compare validation scores, keep the best. Like adjusting oven temperature and baking time across several test batches. SageMaker automatic model tuning automates this search.

Model sources and production hosting

Open-source pre-trained models (for example from JumpStart or public hubs) are fast and cheap to start with and can be fine-tuned. Custom-trained models give maximum control and fit your data but cost more time, data, and expertise. Managed-service models (such as those in Bedrock) require no training at all.

For production, a managed API service (a SageMaker endpoint or Bedrock) reduces operational burden: AWS handles scaling and infrastructure. A self-hosted API on your own compute gives more control over environment and cost tuning but you own patching, scaling, and availability.

MLOps

MLOps applies DevOps discipline to ML: experimentation tracking, repeatable and automated pipelines, scalable infrastructure, managing technical debt (undocumented data dependencies, ad-hoc notebooks), production-readiness checks, continuous monitoring, and retraining. Why it matters: a model is not finished at deployment. Real-world data shifts (drift), so performance decays, and a one-off notebook cannot be reliably reproduced or audited. Pipelines plus Model Registry plus Model Monitor form the typical AWS answer.

Exam tip: Match the tool to the verb: label means Ground Truth; prepare/transform means Data Wrangler; share features means Feature Store; detect bias or explain means Clarify; no-code means Canvas; AutoML means Autopilot; pre-trained starting point means JumpStart; version/approve means Model Registry; orchestrate means Pipelines; detect drift means Model Monitor.

Common trap: Clarify (bias and explainability) is not Model Monitor (drift), though Clarify can also feed bias monitoring. Data Wrangler prepares data; Feature Store stores finished features. Ground Truth labels data; it does not train models. Hyperparameters are not learned parameters.

Evaluating models: the confusion matrix and metrics

For classification, count outcomes in a confusion matrix: true positives (TP), false positives (FP), false negatives (FN), true negatives (TN).

Worked example: a fraud model scores 1,000 transactions, of which 50 are actually fraud. It catches 40 (TP = 40), misses 10 (FN = 10), wrongly flags 20 legitimate ones (FP = 20), and correctly clears 930 (TN = 930).

Predicted fraudPredicted legit
Actually fraudTP = 40FN = 10
Actually legitFP = 20TN = 930
MetricFormulaResultAnswers
Accuracy(TP+TN) / total970/1000 = 97%How often is it right overall?
PrecisionTP / (TP+FP)40/60 = 66.7%Of flagged items, how many were truly fraud?
Recall (sensitivity)TP / (TP+FN)40/50 = 80%Of real fraud, how much did we catch?
F12 x P x R / (P+R)about 0.73Single balance of precision and recall

Notice accuracy looks excellent at 97%, yet a model that always said "legit" would score 95% while catching zero fraud. That is why accuracy misleads on imbalanced data. Choose by the cost of errors: when missing a positive is costly (cancer screening, fraud), favor recall; when false alarms are costly (blocking good customers, spam filtering that hides real mail), favor precision.

AUC-ROC plots the true-positive rate against the false-positive rate across all decision thresholds. The area under the curve summarizes how well the model separates the classes regardless of threshold: 1.0 is perfect, 0.5 is no better than random guessing.

Regression metrics measure numeric error. MAE (mean absolute error) is the average size of errors in the target's own units. RMSE (root mean squared error) squares errors before averaging, so it penalizes large misses more heavily. Lower is better for both.

Business metrics tie the model to value: ROI, cost per user, development and operating cost, customer feedback or satisfaction, and revenue or conversion impact. A model with a great F1 that costs more than it saves is still a failure.

Exam tip: Questions on rare events (fraud, defects, disease) are really asking "do you know accuracy is misleading?" Pick precision, recall, F1, or AUC. If a question names MAE or RMSE, the problem is regression.

Common trap: Precision and recall are easy to swap. Precision looks at what the model flagged (FP in the denominator); recall looks at what truly exists (FN in the denominator). Also, AUC-ROC and F1 are for classification, never for predicting a number.

Key takeaways

  • The lifecycle is a loop: data, EDA, pre-process, features, train, tune, evaluate, deploy, monitor, retrain.
  • Hyperparameters are set by you; parameters are learned.
  • Know each SageMaker tool's single job.
  • Pre-trained and managed options save effort; custom models give control.
  • With imbalanced classes use precision, recall, F1, AUC; for regression use MAE or RMSE; always add business metrics.

Self-check questions

Try to answer first, then reveal and mark yourself. Your score is saved in this browser.

  1. What is the relationship between AI, ML, and deep learning?

    AI is the broadest; ML is a subset of AI; deep learning is a subset of ML. Each narrows the method used to achieve intelligent behavior.

  2. Which learning type uses labeled data? Which finds clusters?

    Supervised uses labeled data; unsupervised (clustering) finds groups. Clustering needs no labels because it discovers structure itself.

  3. An LLM is pre-trained by predicting the next word in huge amounts of unlabeled text. Which learning type is this?

    Self-supervised learning. The labels (the next words) are generated from the data itself.

  4. When is batch inference better than real-time?

    When results are not needed instantly and large volumes can be processed offline, which is cheaper than keeping an endpoint running.

  5. A company needs to compute exact sales tax from a fixed legal rate. Should it use ML?

    No. A deterministic outcome should be implemented with rules or code, because ML predictions are probabilistic.

  6. Which technique predicts a continuous number? Which predicts a category?

    Regression predicts a number; classification predicts a category. The difference is the type of the label.

  7. A model scores 99% on training data but 70% on test data. What is the problem and one fix?

    Overfitting (high variance); fixes include more data, a simpler model, or regularization.

  8. A company wants to extract fields and tables from thousands of scanned invoices. Which service?

    Amazon Textract, because it extracts text, forms, and tables from documents.

  9. A company wants to turn recorded customer calls into text and then detect the sentiment. Which services?

    Amazon Transcribe for speech to text, then Amazon Comprehend for sentiment analysis.

  10. A team wants analysts with no coding skills to build an ML model from a spreadsheet. Which SageMaker capability?

    SageMaker Canvas, which provides visual, no-code model building.

  11. A company wants to check training data and a model for bias and explain predictions. Which SageMaker feature?

    SageMaker Clarify, which detects bias and provides explainability.

  12. Which SageMaker feature detects drift in a deployed model?

    SageMaker Model Monitor, which watches production data and model quality against a baseline.

  13. A fraud model reports 98% accuracy, but only 1% of transactions are fraud. Why might it still be poor, and what should you check?

    It may simply predict "not fraud" every time; check precision, recall, F1, or AUC-ROC instead.

  14. Missing a disease case is far worse than a false alarm. Which metric should you prioritize?

    Recall, because it measures the share of true positives caught (it penalizes false negatives).

  15. Name one technical metric for regression and one business metric for any ML model.

    Technical: MAE or RMSE. Business: ROI or cost per user; these show whether the model delivers value.
