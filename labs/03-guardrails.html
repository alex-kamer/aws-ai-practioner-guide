Lab 3: Guardrails for Amazon Bedrock

Domain: 4 (4.1 responsible AI tools), also 3.2 (prompt risks) and 5.1 (security) Time: about 30-45 minutes Estimated cost: under $1 (guardrail evaluations and model tokens are billed per use)

Prerequisites

  • AWS account with Bedrock access and one text model enabled
  • Complete Lab 1 first (recommended)

Billable resources

Guardrail text evaluations and model invocations, both per use. Nothing runs continuously.

Steps

  1. In Bedrock, open Guardrails > Create guardrail.
  2. Content filters: enable filters (hate, insults, sexual, violence, misconduct) and set strengths. Enable prompt-attack detection.
  3. Denied topics: add one, for example "Investment advice" with a short definition and examples.
  4. Word filters: block a specific custom word or phrase.
  5. Sensitive information filters: add PII types (for example, email, phone) set to mask or block.
  6. Optionally enable contextual grounding check if offered.
  7. Set the blocked-message text, create the guardrail, and create a version.
  8. In the guardrail Test pane (or a playground with the guardrail attached), try:
    • an input on the denied topic
    • an input containing a fake email address and phone number
    • an "ignore all previous instructions" style prompt
    • a normal, harmless question
  9. Note which were blocked, which were masked, and whether it applied to input, output, or both.

Cleanup

Delete the guardrail (and its versions) from the Guardrails page. Nothing else was created.

Exam concepts this demonstrated

  • Guardrails for Amazon Bedrock as a responsible-AI tool (domain 4)
  • Denied topics, content filters, PII redaction, grounding checks
  • Defense against prompt attacks, which is complementary to IAM and encryption (domain 5)
  • Guardrails vs IAM: guardrails control content; IAM controls access
