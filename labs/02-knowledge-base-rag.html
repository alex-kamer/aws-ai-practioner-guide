Lab 2: Knowledge Base (RAG) with Amazon Bedrock

Domain: 3 (3.1 RAG, vector databases, customization cost tradeoffs) Time: about 45-60 minutes Estimated cost: a few dollars if you clean up the same day. Some vector stores (notably OpenSearch Serverless) bill by the hour while they exist. They can cost much more if you leave them running. Check the current Bedrock and vector store pricing pages before you start.

Prerequisites

  • AWS account with Bedrock access, plus access to one embedding model and one text model in your region
  • 2-3 small text or PDF documents you are fine with uploading (public docs are fine; no sensitive data)
  • Complete Lab 1 first (recommended)

Billable resources

  • S3 bucket (tiny)
  • Vector store made for the knowledge base (the main cost; pick the cheapest option the console offers, such as S3 Vectors if available, and do not leave OpenSearch Serverless running)
  • Tokens for the embedding model and the text model

Set an AWS Budget alert (for example, $10) before you begin.

Steps

  1. Create an S3 bucket and upload your documents.
  2. In Bedrock, go to Knowledge Bases > Create knowledge base. Choose S3 as the data source and point to your bucket.
  3. Choose an embedding model and let the console create the vector store for you (note which store it uses).
  4. Create the knowledge base and run Sync so your documents are split into chunks, embedded, and indexed.
  5. Use the Test pane: select a text model and ask a question that only your documents can answer. Check the source citations.
  6. Ask a question that is not in your documents. Notice how the model acts compared with a chat without RAG (Lab 1).
  7. If the console allows it, change the chunking or the number of results it fetches, and see how the answers change.

Cleanup (do this the same day)

  1. Delete the knowledge base.
  2. Delete the vector store it created (for example, OpenSearch Serverless collection, Aurora cluster, or vector bucket). Deleting the knowledge base may not delete it.
  3. Delete the S3 bucket contents and bucket.
  4. Delete any IAM service role made for it, if you do not need it.
  5. Check in the OpenSearch, RDS, and S3 consoles that nothing is left, and look at Billing the next day.

Exam concepts this demonstrated

  • RAG flow: chunk, embed, store in vector DB, retrieve, augment prompt, generate
  • Vector store options (OpenSearch, Aurora/RDS PostgreSQL, Neptune, DocumentDB)
  • RAG vs fine-tuning: RAG needs no retraining and uses up-to-date data (domain 3)
  • Source citations and data origins (domain 5)
